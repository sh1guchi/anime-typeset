# Тайпсеттинг надписей (anime-typeset)

Навык превращает «перевод надписей с таймингами» в готовый тайпсет: русские надписи стоят на месте японских,
выглядят как родные, а японский текст убран — фон под ним восстановлен из самого видео и двигается вместе
с камерой. Сплошных плашек нет: заплатка — это мозаика из прямоугольников цвета фона, которую не видно.

Инструмент: `scripts/typeset.py` (Python + ffmpeg/libass) в папке этого навыка.
Ниже `TS` = `python <папка навыка>/scripts/typeset.py` (папку называет загрузчик навыка: «Base directory»).

**Где править навык.** Если навык склонирован прямо в `~/.claude/skills/anime-typeset` — правь там. Если он
поставлен через `install.bat` из рабочей копии в другом месте (зеркало: `install.bat` копирует свою папку
в `~/.claude/skills`), все правки — код, пресеты, примеры, `SKILL.md`, `references` — вноси в рабочей копии
и после них запускай её `install.bat` (из Git Bash: `cmd //c "<рабочая копия>\install.bat"`), иначе следующая
установка их затрёт. Новые пресеты и примеры конфигов (`examples/`) тоже клади туда.

## Как устроена работа

Ты один раз смотришь кадры и **записываешь решения в `episode.json`**, дальше всё строит инструмент; в конце
смотришь контрольные кадры и правишь только то, что вылезло. Не пиши одноразовые скрипты под каждую надпись —
если чего-то не хватает в инструменте, добавь это в `tslib` (так навык становится лучше с каждой серией).
Правишь подсказки `analyze` (движение карточек, зоны табличек) — прогони быструю проверку против готовых
серий (секунды вместо 3-минутного `analyze`; первый запуск кэширует кадры во временную папку):
`python <папка навыка>/tests/check_analyze.py --draft examples/<серия>.draft.json --truth examples/<серия>.episode.json --video "<видео серии>"`.
Закончил серию — в том же чате отчёт, доработка навыка, регрессия, примеры и уборка (шаг 6): так у проверки
становится больше эталонов, а навык — лучше с каждой серией без отдельного захода.

Рабочая папка серии: `<папка видео>/_typeset/<имя видео>/` — там `episode.json`, `analysis/`, `lines/`,
`check/`, `cache/`. Её можно удалить после сдачи, кроме `episode.json` (это рецепт серии, пригодится для
следующей — у тайтла надписи повторяются).

## Шаг 0. Входные данные и проверка

Нужно: видео, файл надписей переводчика (.ass: тайминги + русский текст, позиции не важны), по желанию —
файл диалоговых сабов (если надписи надо влить туда) и папка шрифтов релиза.

```
TS doctor        # ffmpeg с libass, numpy, opencv-python, pillow, fonttools
```
Если чего-то нет — `pip install numpy opencv-python pillow fonttools`; ffmpeg должен уметь фильтр `subtitles`.

Если тайтл уже встречался — проверь `presets/` (например `black-clover.json`) и `examples/` (готовый конфиг
прошлой серии). Пресет = стили и параметры повторяющихся элементов тайтла. Нового тайтла нет в пресетах —
начни с `default`, а по ходу работы создай `presets/<тайтл>.json` (это и есть «обучение» навыка).

### Грабли окружения
- **Кириллица в путях:** Git Bash портит не-ASCII аргументы командной строки (питон получает `????`).
  Команды с такими путями (`analyze --signs ...надписи...`) запускай через PowerShell; остальным хватает
  `-c episode.json`, а внутри JSON кириллица в путях работает.
- **Соотношение сторон** берётся из видео: координаты анализа — ширина 1920, высота по аспекту
  (1080 для 16:9, 816 для 2.35:1). Все `zone`/`box`/`pos` — в этих пикселях.
- **Вшитые надписи в исходнике** (японские ТВ-релизы китайских/корейских тайтлов, «хардсаб» Erai/B-Global):
  на кадре может быть и оригинал, и чужой перевод надписи. Спроси пользователя, что закрывать; по умолчанию
  закрывай оригинал, а вшитую строку — тоже, если она мешает (это отдельная зона).

## Шаг 1. Анализ

```
TS analyze --video "<видео>" --signs "<надписи.ass>" --work "<папка видео>/_typeset/<имя>"
```
Делает для каждой надписи (строки с одинаковым таймингом группируются): поиск склеек вокруг тайминга и
подгонку к ним (`frames` vs `source_frames`), оценку движения кадра (static / linear / path / zoom / unknown),
поиск именных карточек с орнаментом, контактный лист `analysis/<id>.jpg` (кадр до, первый, средний,
последний, после; на среднем — найденные карточки (зелёные) и рамки строк переводчика (оранжевые);
шестой кадр — **оформление переводчика, отрисованное поверх кадра**) и черновик `episode.json`
(в нём же сохраняются строки и стили исходника: `source_lines`, `source_styles`, `source_events`).

Что в черновике:
- `frames` — **тайминг по самому кадру**: у карточек и табличек-оверлеев analyze меряет, когда японский текст
  реально на экране (с проявлением и затуханием), и ставит эти кадры вместо тайминга переводчика
  (`source_frames`); замер — в `_timing` (`on_screen`, `fade_in`/`fade_out` — кадры проявления оригинала,
  `translator`). Резкая граница ставится точно; на плавном проявлении тайминг переводчика остаётся, если он не
  дальше секунды; через склейку затухание не тянется. Текст, который сам движется (зумящееся лого, бегущая
  строка), не мерится — `_timing.note: the text moves on screen`, кадры ставь по `grid`;
- `preset` — угадан по словам `match` пресетов в имени видео/надписей (иначе `default`); проверь;
- у карточек `motion` уже по фону **рядом с карточкой** (static / linear / path с предложенным `roi`; в
  `_analyze` — замеры). `static`, если компенсация трека не делает фон вокруг стабильнее (трек тогда шёл
  за волосами/рукой персонажа, а небо/плащ стоят); у остальных — движение всего кадра, это только подсказка;
- у табличек `zones` найдены по строке почти белых (или почти чёрных) глифов около рамки CR (CR часто
  ставит перевод рядом/над/под оригиналом), низ зоны — на 1 px выше линии со стрелками под глифами;
  тип `plate`, `detect.polarity` и режим `clean` предложены. Отброшенная тень глифов в зону входит только
  отступом — если она длинная, добавь `detect.shadow` и расширь зону;
- где решить нельзя — `TODO` (тип, тексты, `out`). Все команды, включая `grid`/`ruler`, работают и на черновике.

### Исходник уже оформлен (Crunchyroll / Erai-raws)
Пользователь обычно берёт надписи CR — они уже стоят по месту: `\pos`, повороты, `\fad`, вытирания `\clip`,
но японский текст **не закрыт**, а перевод часто стоит рядом с оригиналом (над ним), стилями диалога.
Это бесплатные замеры: рамка строки CR = где искать оригинал (черновые `zones` — глифы, найденные около неё).
Для каждой надписи выбери:
- **маска + текст CR** — японский стираем, строки CR оставляем как есть: `"text": {"source": true}`
  (у карточек — `"source_text": true`). Годится, когда оформление CR приличное (перспектива, анимации).
  Если CR поставил текст *рядом* с оригиналом, после маски его лучше сдвинуть на место оригинала —
  тогда это уже своё оформление (обычный `text`), CR служит только подсказкой;
- **переоформить** в стиле оригинала (пресет, свои шрифты) — когда CR сделал «Таймсом по центру»;
- **оставить как у CR без маски** — `type: text` + `{"source": true}` (сложный 3D, быстрые вспышки).

Бывает, что «оформленные» надписи CR — это просто строки стилем диалога сверху по центру (`{\an8}`, без `\pos`;
так CR делает фильмы). analyze это видит (ни у одной строки нет `\pos`/`\move`/`\clip`): пишет об этом в
`analysis.md`, зоны около рамок CR не ищет, тип — `TODO text|plate`. Ищи иероглифы по листам сам; почти всё —
переоформление (`text` в стиле оригинала, `text` + `track`, маска там, где надпись на неподвижной или жёстко
движущейся плоскости).

**Песни (OP/ED/вставки) в файле надписей** (актёр/стиль `Песня`, song, OP/ED, karaoke…): analyze их не
анализирует, а сразу делает по элементу `song-NN` на строку (`type: text`, тайминг переводчика; если в пресете
есть набор `song` — переоформляет им сверху по центру, иначе оставляет строку CR как есть). Другой фильтр —
`--songs "<regex>"`, отключить — `--songs ""`. Добавить группу строк позже: `TS add -c episode.json --match
Песня --preset song`. Посмотри `sheet` по песням: на титрах (ED, вставка с роликом титров) сдвигай текст на
свободную сторону кадра (`pos`, `an`, `maxw` + `fit: shrink`).

**Посмотри каждый лист** (Read на jpg) и `analysis.md` — по 1–2 картинки за ответ: много Read картинок в
одном ответе обрезаются (`[media removed: request limit]`). Для обзора — один общий лист (`TS sheet`).
Для каждой надписи реши:
- что там на экране (карточка, табличка, титр, лого, текст на объекте, записка…);
- тайминг: у карточек и оверлеев его уже поправил analyze (см. `_timing`). Правь его и дальше сам — это не
  «расхождение», которое надо только сообщить: исправил зону/тип — `TS timing -c episode.json <id> --apply`;
  текст, который едет со сценой, и `text` — дай `"timing": {"box": [x0,y0,x1,y1]}` (где стоит японский) и тот же
  `timing --apply`, или найди кадры по `TS grid`. Свои кадры, которые трогать нельзя, — `"timing": {"lock": true}`.
  Оригинал проявляется/гаснет (`_timing.fade_in`/`fade_out`) — русский текст так же (`fade_frames` / `fade`);
- двигается ли то, что под текстом (камера, зум, персонаж проходит перед надписью);
- совпадает ли перевод со смыслом японского. Смысловые расхождения **не исправляй** — запиши и скажи
  пользователю (тайминг — исправляй, см. выше).

## Шаг 2. Заполнить episode.json

Полное описание полей — `references/config.md`. Выбор типа:

| На экране | type | движение | заметки |
|---|---|---|---|
| Именная карточка с орнаментом (титул + имя) | `card` | `static` / `linear` / `path` | геометрия ищется сама по `box`; для движущегося фона нужен `motion.roi` — кусок фона рядом с карточкой, который двигается так же |
| Табличка / карточка / этикетка в рамке (однотонная или градиент), стоит на месте | `plate` + зона `{"box": ..., "fill": "auto"}` | static | внутренность заменяется целиком до рамки ровными полосами (const / rows / cols по остатку); analyze подсказывает сам |
| Табличка/надпись на однотонном или мягком фоне, статичный кадр | `plate` + `clean.mode: inpaint` | static | гладкая заливка; на текстурах (кирпич) мылит — тогда `ref` |
| Надпись появляется на уже идущем плане (есть чистые кадры до неё), зум/пан | `plate` + `clean.mode: ref` | `affine` | чистый фон берётся из кадров до появления текста и ведётся трекингом; снег/искры, которые медиана `pre` не убрала, — `clean.fill: "lama"` (LaMa только там, где чистые кадры расходятся); тёмные призраки ореола — `halo: 10` |
| Текст на объекте сцены (экран, доска, вывеска), камера едет/зумит | `plate` + `attached: true` + `clean.mode: inpaint` | `affine` | заплатка и русский текст едут вместе с объектом; несколько полей — `zones`; тёмный текст — `detect.polarity: dark` |
| Титр с первого кадра плана (чистых кадров нет), план зумится/едет | `plate` + `clean.mode: inpaint` (без `attached`) | `affine` | заливка кадра `clean.ref` ведётся треком; на текстуре (зубцы, кирпич, дерево, бумага) — `clean.fill: "lama"` (нейросеть продолжает фактуру; без неё будет мыло), пороги `detect` по `TS probe`. Где чистые кадры есть — всегда `ref`, не LaMa |
| Подпись к лого, которое зумится; поверх пролетают силуэты | `follow` | трекинг масштаба | `occluders` прячет текст за тёмными силуэтами |
| Закрыть нельзя или не нужно (сложный 3D, перекрытие персонажами, короткий текст) | `text` | — | русский текст рядом с японским, в его стиле |
| То же, но объект/камера заметно едет (клинок, вывеска на наклоне, карта на зуме) | `text` + `track` | `shift` / `affine` | текст едет за `roi`; позиции — в кадре `track.ref` |
| Наклонный текст в нарисованной рамке (овал на карте) | `plate` + `inside` | как у plate | маска только внутри эллипса/многоугольника, рамка не стирается |
| Надпись под углом / в перспективе (вывеска на стене, наклонный титр) | любой + `text.quad` | как у типа | русский вписан в плоскость точной перспективой (`TS place`); углы перспективной вывески — по её краям |

Измерения (не угадывай координаты — меряй):
```
TS ruler -c episode.json --frames 22583:22628 --box 1040,590,1900,790 --out r.png [--std]
TS grid  -c episode.json --frames 22583:22628:6 --crop 900,500,1920,850 --out g.jpg
TS geom  -c episode.json --frames 22583:22628 --box 1040,590,1900,790
TS track -c episode.json --frames 22848:22969 --roi 800,250,300,420 --roi 120,350,380,420
TS probe -c episode.json --frames 4200:4253 --box 715,893,1195,997 [--bg 715,820,1195,890]
TS timing -c episode.json [ids] [--apply]   # когда японский на экране (резкие границы, проявление, склейки)
TS lama-ab -c episode.json id [..]          # табличка без LaMa и с ней на одних кадрах: оставить LaMa или нет
TS place -c episode.json id --box ...        # плоскость оригинала (наклон / --quad) и русский текст в ней
TS fonts -c episode.json --match id --category serif   # шрифт по штрихам оригинала: установленные + Google Fonts
TS fonts --cyr --grep garamond
```
`ruler` — медиана кадров с линейкой в px (координаты всегда в 1920×1080, даже для 4K-исходника);
`--std` добавляет карту движения (светлое = меняется во времени — туда статичную заплатку ставить нельзя).
`track` — сдвиг фона по каждому ROI (2D и по осям) без сборки: выбрать ROI и `axis` за секунды.
`probe` — яркость глифов и фона → пороги `detect`; где кончаются глифы и начинается линия → низ зоны;
цвет штриха и фона сразу в формате ASS (`glyph colour RGB (...) = \c&H...&`); рамка таблички → её внутренность.

Править конфиг — не самописными скриптами (кириллица в heredoc Git Bash ломается), а командами:
```
TS set   -c episode.json yuno.mask_dil=14 yuno.motion.axis=y "@preset=black-clover"   # пусто после = удалить
TS set   -c episode.json --from patch.json   # много правок сразу: {"@": {...}, "items": {"id": {...}}}; "id": null — удалить элемент
TS split -c episode.json salli          # элемент с несколькими карточками -> по элементу на карточку
```
`patch.json` пиши обычным Write (UTF-8, кириллица и `\\N` без экранирования оболочки); значение `null` удаляет
ключ, новый id с `frames` добавляет элемент. Словари/списки в `set id.key=...` из PowerShell не передавай —
кавычки съедаются, и в конфиг попадает строка (сборка падает `'str' object has no attribute 'get'`).

**Шрифт** подбирай под оригинал — из установленных **и** из Google Fonts (≈300 бесплатных семейств с
кириллицей, OFL — их можно вшивать в релиз; скачиваются сами в библиотеку шрифтов):
```
TS fonts -c episode.json --match <id> --category serif,display --with "Ponomar,Old Standard TT:700" [--box ...] [--text "..."]
```
Выбор — вместе: ты по жанру, скрипт по штрихам, итог глазами на одном листе.
1. Сначала **сам** определи по кадру категорию оригинала (засечки / рубленый / кисть-рукопись / декоративный,
   готика) — `--category` (можно две через запятую). Без неё рейтинг смешивает стили. По штрихам инструмент
   ловит вес и категорию, но не «характер» (изящество, готику, кисть конкретного вида) — это решаешь ты:
   **назови 2–4 своих кандидата** под жанр — из `references/fonts.md` (шпаргалка Google-шрифтов по жанрам) и
   установленных (`TS fonts --cyr --grep ...`) — и передай `--with` (вес `"Family:700"` или ближайший сам).
2. Инструмент меряет штрихи японского текста (толщина, разброс толстых и тонких, рваность края) и тех же
   величин у каждого начертания на русской строке, ранжирует (толщина — в пикселях на экране: русский мельче
   иероглифов, ему нужен относительно более жирный шрифт); **сам отсекает** штрих тоньше 1.8 px при
   реальном кегле (`--min-px`: «почти невидный карандаш»), моноширинную кириллицу японских шрифтов
   («Ц а р с т в о») и шрифты без нужных букв. Лист `check/fonts_<id>.jpg`: оригинал, **первым — текущий
   шрифт элемента** (стиль пресета, `current`), за ним твои `--with` (замерены и помечены `! thin` /
   `! full-width` / `! missing letters`, но не выкинуты), дальше топ-8 скрипта — поверх заплатки (если элемент
   собран) в цвете оригинала, на месте и в размере надписи.
3. Выбирай глазами из листа. Шрифт пресета (подобран руками под тайтл) меняй, только если кандидат явно
   лучше: место в рейтинге не довод (на BC 2-01 пользователь оставил Moyenage в названии). **Если сомневаешься или хороших кандидатов несколько** (инструмент пишет
   `the best ones are close`, или они разного характера) — **спроси пользователя**: покажи лист (SendUserFile)
   и задай вопрос (AskUserQuestion) с 2–4 лучшими вариантами (имя + чем отличаются). Не выбирай молча.
4. Выбранный онлайн-шрифт уже в библиотеке; имя для стиля и флаг жирности печатает `--match`
   (или `TS fonts --get "Family:600"`). `assemble` кладёт все шрифты надписей в `надписи/шрифты/` для мукса.
Ручная проба своих кандидатов: `TS fonts -c episode.json --try "A,B,C" --frame N --text "..." --pos x,base
--em 90 --colour "&H..&" --crop ... --out f.jpg`. Для тайтла с пресетом шрифты уже выбраны — пропусти, если
оформление не новое.

## Шаг 3. Сборка и проверка

```
TS build -c episode.json            # всё, 4 элемента параллельно (-j N); или перечисли id: ... fuego jack
```
На каждый элемент: `lines/<id>.json` и `check/<id>.jpg` (рендер через libass на первом/среднем/последнем кадре,
для движения — 5 кадров). **Открой каждый check** и пройди чек-лист:
1. японский текст и его свечение исчезли целиком, нет «призраков» по краям;
2. заплатку не видно: нет квадратиков, ступенек, пятен другого цвета, резкой границы;
3. на движении фон под заплаткой едет вместе с кадром (сравни первый и последний кадр);
4. русский текст на месте японского: та же базовая линия, центр, размер, не вылезает за орнаменты;
5. стиль совпадает: цвет, обводка/свечение, тень, размытость краёв как у оригинала;
6. ничего лишнего не закрыто (пуговицы, волосы, руки, элементы карточки).
Тонкие края на чек-листе мелкие — смотри крупно: `TS check -c episode.json yuno --frames 24800,24840
--zoom 120,740,720,1000 [--compare]` (`--compare`: оригинал | результат | разница ×4). Общий лист всех
элементов — `TS sheet -c episode.json`. Чек рисует элемент один: если на тех же кадрах есть другие надписи
(название + подзаголовок под лого, две таблички), смотри их вместе — `TS check ... <id> --with-others`;
`assemble` сам перечисляет пары, которые на экране одновременно и в одной области.
Плохо — поправь параметры этого элемента (подсказки в `references/troubleshooting.md`) и пересобери только его.

**LaMa — только там, где она лучше.** Каждый элемент с `clean.fill: "lama"` сравни с тем же элементом без неё
на одних кадрах: `TS lama-ab -c episode.json <id>` (оригинал | без LaMa | с LaMa, крупно, плюс шов по краю
заплатки). Если вариант с LaMa **неприемлем** — пятно светлее/темнее фона, выдуманные детали, которых нет в сцене
(окна, предметы, лишние линии), смаз чёткой структуры, шов хуже, чем без неё, цвет поехал, — LaMa для **этой**
надписи отбрасывается: `TS set -c episode.json <id>.clean.fill=` и пересобрать. Не «лечи» LaMa долгими
итерациями: одна-две попытки (маска, `lama_pad`), потом отказ. Остальные надписи решаются отдельно. В итоге и
в отчёте — где LaMa оставлена, где отброшена и почему.

## Шаг 4. Сборка файла, превью, сабы

```
TS assemble -c episode.json             # -> cfg "out" (оригинал файла — копией в подпапку "исходники")
TS preview  -c episode.json             # mp4 со всеми надписями подряд, со звуком
TS merge    -c episode.json             # влить в сабы cfg "subs": старые надписи удаляются, слои — под диалогом
```
Строки заплаток при сборке уже ужаты без изменения картинки (~−23%, см. technique.md «Размер файла»).
Файлы, собранные до этого, ужимает `TS compact <надписи.ass> <сабы.ass>` (копия — «исходники/… (до сжатия)»).
Копии оригиналов, которые делают `assemble`/`merge`/`compact`, лежат в подпапке `исходники` рядом с файлом —
в папке релиза остаются только готовые файлы.
`merge` удаляет из сабов **только** строки переводчика тех надписей, что есть в конфиге и собраны
(точное совпадение времени, стиля и текста — CR делает надписи стилями диалога, удаление по стилю снесло бы
диалог), и строки прошлого merge (все наши строки помечены `Effect = ts`); `merge_drop_styles` — явный список
стилей, если надо. Остальные надписи переводчика остаются в сабах. Стиль удаляется, только если им больше
никто не пользуется. Добавляет `YCbCr Matrix` — без этой строки цвет заплаток поедет, не удаляй её.
merge сам сверяет диалог до и после построчно без поля Layer (`dialogue lines: 304 -> 304  OK: text, times,
style, actor and order unchanged`); любое другое сообщение — разберись, прежде чем сдавать.

## Шаг 5. Итог пользователю

Коротко: что сделано по каждому типу надписей, где лежат файлы, какие шрифты положить в контейнер,
что посмотреть глазами в превью (ты видишь стоп-кадры — дрожание/мерцание в движении лучше проверит человек),
где поправлен тайминг (было → стало: надпись и кадры/таймкоды), расхождения перевода (их не исправляешь —
только перечисляешь). Приложи `preview.mp4` и общий контактный лист.

## Шаг 6. В этом же чате: отчёт, доработка навыка, примеры, уборка

Серия сдана — не жди отдельной просьбы и не оставляй это «на следующий чат». Всё ниже делается сразу, в том же
ответе/чате, по порядку:

1. **Отчёт** `<рабочая копия навыка>/feedback/<тайтл>-<NN>.md` (фильм: `<тайтл>-movie-<N>`, папку создай) по
   шаблону `references/report.md`: каждая надпись (тип, режим, сколько сборок, что не вышло с первого раза и
   почему, что подбирал руками), падения инструмента (команда + текст ошибки + обход), что делал мимо
   инструмента, где врали SKILL.md/справочники/analyze, что осталось неидеальным (с таймкодами), время по
   этапам, предложения по важности. Конкретно: кадры, команды, тексты ошибок; без воды.
2. **Доработка по отчёту** — в рабочей копии навыка, сразу:
   - падения и неверные результаты инструмента — исправить (с воспроизведением до и после);
   - всё, что делал своими скриптами или руками и что повторится, — в команду/опцию `typeset.py`/`tslib`;
   - неверные подсказки analyze — поправить эвристику, если она общая (не под одну серию);
   - остальные предложения — по важности. Не сделал — в отчёт (п. 8) с причиной («нужно видео другой серии»,
     «крупная переделка»). Поправки, которые меняют картинку этой серии, — пересобери её элементы,
     `assemble`/`merge`/`preview` заново и проверь, что стало лучше.
3. **Регрессия** — на тех `examples/`, чьё видео есть на диске (`"video"` в конфиге примера; пути там
   относительно `_typeset/<имя>/`), **только в scratchpad**: рабочие папки, `надписи/`, `сабы/` других серий
   не трогай. Код до правок — `git -C <рабочая копия> archive HEAD scripts presets | tar -x -C <scratch>/head`;
   конфиг примера — копией с абсолютным `video` и `out` в scratch; собери затронутые элементы старым и новым
   кодом и сравни (`check --compare`, разница рендеров). Правил analyze — `tests/check_analyze.py` по каждому
   примеру с видео. Чего не проверил (нет видео) — в отчёт.
4. **Документация**: `SKILL.md`, `references/config.md` (новые поля), `troubleshooting.md` (симптом → что
   крутить), `technique.md`, `fonts.md` (удачный / выбранный пользователем шрифт — в его жанр); заметки тайтла `references/<тайтл>.md` — только общее для тайтла (карточки,
   таблички, лого), решения этой серии — в `examples/<серия>.notes.md`. Новый тайтл — `presets/<тайтл>.json`
   (с `match`).
5. **Примеры**: `examples/<серия>.episode.json` (рецепт серии) и `examples/<серия>.draft.json` (черновик
   analyze без `source_events`/`source_styles`), пути — относительно `_typeset/<имя>/` (`"../../<видео>"`),
   `_comment` — что это за серия и когда.
6. `install.bat` рабочей копии (если навык ставится через него). Git — не коммить и не пушить без просьбы:
   в итоге перечисли изменённые файлы (`git status --short`).
7. **Уборка** (рецепт уже в `examples/`): рабочую папку `_typeset/<имя>/` (кэши, листы, чеки), свои
   scratch-рендеры и временные файлы — в Корзину, не насовсем:
   `powershell -c "Add-Type -A Microsoft.VisualBasic; [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteDirectory('<путь>','OnlyErrorDialogs','SendToRecycleBin')"`.
   В папках релиза (`надписи/`, `сабы/`) — только готовые файлы и `исходники/`.
8. **Последнее сообщение**: 3–6 строк — ссылка на отчёт, что поменялось в навыке, что проверено регрессией и
   что нет.

Тестовый прогон «с нуля» (пользователь просит не подглядывать): `examples/<эта серия>.*` и её
`*.notes.md` не открывай до сдачи серии; для регрессии и обновления примеров после сдачи — можно.

## Когда что-то нестандартное

- Персонаж проходит перед надписью → `occluders`: у `follow` — по тёмным силуэтам, у статичной `card` — по
  разнице кадра и чистого фона под заплаткой (покадровый `\iclip`). Для остальных типов: обрежь время/зону
  так, чтобы маска не лезла на персонажа, или сделай `text` без маски и скажи пользователю. Если такое
  повторяется — добавь `occluders` в нужный билдер.
- «Ящик» вокруг заплатки на светлом небе у движущейся карточки → сначала `check --zoom --compare`: обычно это
  ореол японского текста за краем маски (по умолчанию его забирает `halo`; проверь, что в логе сборки есть
  строка `halo: patch grows by ...`), реже — модель свечения (`"glow": "fit"`).
- Надпись под углом / в перспективе (вывеска на стене, доска, повёрнутый титр) → текст с `"quad"`: русский
  вписывается в плоскость четырёхугольника точной перспективой (рисунок из контуров шрифта, одинаково во всех
  плеерах и разрешениях; стиль — обводка, тень, blur — работает как у текста). Четырёхугольник:
  `TS place -c episode.json <id> --box <одна строка оригинала>` — находит наклон строки (повёрнутый
  прямоугольник) и показывает русский в нём; сходящиеся линии по одной строке текста ненадёжны, поэтому для
  настоящей перспективы бери углы **самой вывески/доски** по `ruler` и давай `--quad x,y,...` (TL TR BR BL).
  `\frx\fry` для перспективы не используй: камера libass стоит в пикселях видео плеера — 4K-файл, его
  1080p в веб-плеере и наш чек покажут разную перспективу.
- Огромный размер файла (>1 МБ на элемент) → крупнее `encode.block`, меньше `maxK`, `rect_clip`; на быстрых
  проездах детали всё равно не видны.
- Что-то не получается за 2–3 итерации → вариант `text` без маски лучше, чем видимая заплатка.
