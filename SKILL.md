# Тайпсеттинг надписей (anime-typeset)

Навык превращает «перевод надписей с таймингами» в готовый тайпсет: русские надписи стоят на месте японских,
выглядят как родные, а японский текст убран — фон под ним восстановлен из самого видео и двигается вместе
с камерой. Сплошных плашек нет: заплатка — это мозаика из прямоугольников цвета фона, которую не видно.

Инструмент: `scripts/typeset.py` (Python + ffmpeg/libass) в папке этого навыка.
Ниже `TS` = `python <папка навыка>/scripts/typeset.py` (папку называет загрузчик навыка: «Base directory»).

**Где править навык.** Если навык склонирован прямо в `~/.claude/skills/anime-typeset` — правь там. Если он
поставлен через `install.bat` из рабочей копии в другом месте (зеркало: `install.bat` копирует свою папку
в `~/.claude/skills`), все правки — код, пресеты, примеры, `SKILL.md`, `references` — вноси в рабочей копии
и после них запускай её `install.bat` (из Git Bash: `cmd //c "<рабочая копия>\install.bat"`), иначе следующая
установка их затрёт. Новые пресеты и примеры конфигов (`examples/`) тоже клади туда.

## Как устроена работа

Ты один раз смотришь кадры и **записываешь решения в `episode.json`**, дальше всё строит инструмент; в конце
смотришь контрольные кадры и правишь только то, что вылезло. Не пиши одноразовые скрипты под каждую надпись —
если чего-то не хватает в инструменте, добавь это в `tslib` (так навык становится лучше с каждой серией).
Правишь подсказки `analyze` (движение карточек, зоны табличек) — прогони быструю проверку против готовых
серий (секунды вместо 3-минутного `analyze`; первый запуск кэширует кадры во временную папку):
`python <папка навыка>/tests/check_analyze.py --draft examples/<серия>.draft.json --truth examples/<серия>.episode.json --video "<видео серии>"`.
Закончил серию — положи в `examples/` её конфиг и черновик `analyze` (`<серия>.draft.json`, без
`source_events`/`source_styles`): так у проверки становится больше эталонов.

Рабочая папка серии: `<папка видео>/_typeset/<имя видео>/` — там `episode.json`, `analysis/`, `lines/`,
`check/`, `cache/`. Её можно удалить после сдачи, кроме `episode.json` (это рецепт серии, пригодится для
следующей — у тайтла надписи повторяются).

## Шаг 0. Входные данные и проверка

Нужно: видео, файл надписей переводчика (.ass: тайминги + русский текст, позиции не важны), по желанию —
файл диалоговых сабов (если надписи надо влить туда) и папка шрифтов релиза.

```
TS doctor        # ffmpeg с libass, numpy, opencv-python, pillow, fonttools
```
Если чего-то нет — `pip install numpy opencv-python pillow fonttools`; ffmpeg должен уметь фильтр `subtitles`.

Если тайтл уже встречался — проверь `presets/` (например `black-clover.json`) и `examples/` (готовый конфиг
прошлой серии). Пресет = стили и параметры повторяющихся элементов тайтла. Нового тайтла нет в пресетах —
начни с `default`, а по ходу работы создай `presets/<тайтл>.json` (это и есть «обучение» навыка).

### Грабли окружения
- **Кириллица в путях:** Git Bash портит не-ASCII аргументы командной строки (питон получает `????`).
  Команды с такими путями (`analyze --signs ...надписи...`) запускай через PowerShell; остальным хватает
  `-c episode.json`, а внутри JSON кириллица в путях работает.
- **Соотношение сторон** берётся из видео: координаты анализа — ширина 1920, высота по аспекту
  (1080 для 16:9, 816 для 2.35:1). Все `zone`/`box`/`pos` — в этих пикселях.
- **Вшитые надписи в исходнике** (японские ТВ-релизы китайских/корейских тайтлов, «хардсаб» Erai/B-Global):
  на кадре может быть и оригинал, и чужой перевод надписи. Спроси пользователя, что закрывать; по умолчанию
  закрывай оригинал, а вшитую строку — тоже, если она мешает (это отдельная зона).

## Шаг 1. Анализ

```
TS analyze --video "<видео>" --signs "<надписи.ass>" --work "<папка видео>/_typeset/<имя>"
```
Делает для каждой надписи (строки с одинаковым таймингом группируются): поиск склеек вокруг тайминга и
подгонку к ним (`frames` vs `source_frames`), оценку движения кадра (static / linear / path / zoom / unknown),
поиск именных карточек с орнаментом, контактный лист `analysis/<id>.jpg` (кадр до, первый, средний,
последний, после; на среднем — найденные карточки (зелёные) и рамки строк переводчика (оранжевые);
шестой кадр — **оформление переводчика, отрисованное поверх кадра**) и черновик `episode.json`
(в нём же сохраняются строки и стили исходника: `source_lines`, `source_styles`, `source_events`).

Что в черновике:
- `preset` — угадан по словам `match` пресетов в имени видео/надписей (иначе `default`); проверь;
- у карточек `motion` уже по фону **рядом с карточкой** (static / linear / path с предложенным `roi`; в
  `_analyze` — замеры). `static`, если компенсация трека не делает фон вокруг стабильнее (трек тогда шёл
  за волосами/рукой персонажа, а небо/плащ стоят); у остальных — движение всего кадра, это только подсказка;
- у табличек `zones` найдены по строке почти белых (или почти чёрных) глифов около рамки CR (CR часто
  ставит перевод рядом/над/под оригиналом), низ зоны — на 1 px выше линии со стрелками под глифами;
  тип `plate`, `detect.polarity` и режим `clean` предложены. Отброшенная тень глифов в зону входит только
  отступом — если она длинная, добавь `detect.shadow` и расширь зону;
- где решить нельзя — `TODO` (тип, тексты, `out`). Все команды, включая `grid`/`ruler`, работают и на черновике.

### Исходник уже оформлен (Crunchyroll / Erai-raws)
Пользователь обычно берёт надписи CR — они уже стоят по месту: `\pos`, повороты, `\fad`, вытирания `\clip`,
но японский текст **не закрыт**, а перевод часто стоит рядом с оригиналом (над ним), стилями диалога.
Это бесплатные замеры: рамка строки CR = где искать оригинал (черновые `zones` — глифы, найденные около неё).
Для каждой надписи выбери:
- **маска + текст CR** — японский стираем, строки CR оставляем как есть: `"text": {"source": true}`
  (у карточек — `"source_text": true`). Годится, когда оформление CR приличное (перспектива, анимации).
  Если CR поставил текст *рядом* с оригиналом, после маски его лучше сдвинуть на место оригинала —
  тогда это уже своё оформление (обычный `text`), CR служит только подсказкой;
- **переоформить** в стиле оригинала (пресет, свои шрифты) — когда CR сделал «Таймсом по центру»;
- **оставить как у CR без маски** — `type: text` + `{"source": true}` (сложный 3D, быстрые вспышки).

**Посмотри каждый лист** (Read на jpg) и `analysis.md`. Для каждой надписи реши:
- что там на экране (карточка, табличка, титр, лого, текст на объекте, записка…);
- совпадает ли тайминг с появлением/исчезновением японского текста (подогнанный `frames` обычно верен;
  если текст появляется не на склейке — найди кадр по `TS grid`);
- двигается ли то, что под текстом (камера, зум, персонаж проходит перед надписью);
- совпадает ли перевод со смыслом японского. Расхождения **не исправляй молча** — запиши и скажи пользователю.

## Шаг 2. Заполнить episode.json

Полное описание полей — `references/config.md`. Выбор типа:

| На экране | type | движение | заметки |
|---|---|---|---|
| Именная карточка с орнаментом (титул + имя) | `card` | `static` / `linear` / `path` | геометрия ищется сама по `box`; для движущегося фона нужен `motion.roi` — кусок фона рядом с карточкой, который двигается так же |
| Табличка / карточка / этикетка в рамке (однотонная или градиент), стоит на месте | `plate` + зона `{"box": ..., "fill": "auto"}` | static | внутренность заменяется целиком до рамки ровными полосами (const / rows / cols по остатку); analyze подсказывает сам |
| Табличка/надпись на однотонном или мягком фоне, статичный кадр | `plate` + `clean.mode: inpaint` | static | гладкая заливка; на текстурах (кирпич) мылит — тогда `ref` |
| Надпись появляется на уже идущем плане (есть чистые кадры до неё), зум/пан | `plate` + `clean.mode: ref` | `affine` | чистый фон берётся из кадров до появления текста и ведётся трекингом |
| Текст на объекте сцены (экран, доска, вывеска), камера едет/зумит | `plate` + `attached: true` + `clean.mode: inpaint` | `affine` | заплатка и русский текст едут вместе с объектом; несколько полей — `zones`; тёмный текст — `detect.polarity: dark` |
| Титр с первого кадра плана (чистых кадров нет), план зумится/едет | `plate` + `clean.mode: inpaint` (без `attached`) | `affine` | гладкая заливка кадра `clean.ref` ведётся треком; на текстуре (зубцы, кирпич) под буквами будет мыло — держи маску минимальной, пороги `detect` по `TS probe` |
| Подпись к лого, которое зумится; поверх пролетают силуэты | `follow` | трекинг масштаба | `occluders` прячет текст за тёмными силуэтами |
| Закрыть нельзя или не нужно (сложный 3D, перекрытие персонажами, короткий текст) | `text` | — | русский текст рядом с японским, в его стиле |

Измерения (не угадывай координаты — меряй):
```
TS ruler -c episode.json --frames 22583:22628 --box 1040,590,1900,790 --out r.png [--std]
TS grid  -c episode.json --frames 22583:22628:6 --crop 900,500,1920,850 --out g.jpg
TS geom  -c episode.json --frames 22583:22628 --box 1040,590,1900,790
TS track -c episode.json --frames 22848:22969 --roi 800,250,300,420 --roi 120,350,380,420
TS probe -c episode.json --frames 4200:4253 --box 715,893,1195,997 [--bg 715,820,1195,890]
TS fonts --cyr --grep garamond
```
`ruler` — медиана кадров с линейкой в px (координаты всегда в 1920×1080, даже для 4K-исходника);
`--std` добавляет карту движения (светлое = меняется во времени — туда статичную заплатку ставить нельзя).
`track` — сдвиг фона по каждому ROI (2D и по осям) без сборки: выбрать ROI и `axis` за секунды.
`probe` — яркость глифов и фона → пороги `detect`; где кончаются глифы и начинается линия → низ зоны;
цвет штриха и фона сразу в формате ASS (`glyph colour RGB (...) = \c&H...&`); рамка таблички → её внутренность.

Править конфиг — не самописными скриптами (кириллица в heredoc Git Bash ломается), а командами:
```
TS set   -c episode.json yuno.mask_dil=14 yuno.motion.axis=y "@preset=black-clover"   # пусто после = удалить
TS set   -c episode.json --from patch.json   # много правок сразу: {"@": {...}, "items": {"id": {...}}}
TS split -c episode.json salli          # элемент с несколькими карточками -> по элементу на карточку
```
`patch.json` пиши обычным Write (UTF-8, кириллица и `\\N` без экранирования оболочки); значение `null` удаляет
ключ, новый id с `frames` добавляет элемент. Словари/списки в `set id.key=...` из PowerShell не передавай —
кавычки съедаются, и в конфиг попадает строка (сборка падает `'str' object has no attribute 'get'`).

Шрифт подбирай под оригинал (засечки/рубленый/кисть/готика, насыщенность, ширина) из установленных
кириллических; рендери кандидатов поверх кадра и выбирай глазами:
`TS fonts -c episode.json --try "Buxton Sketch,Caveat,Ink Free" --frame 4579 --text "Способы решения:" --pos 1100,400 --em 90 --colour "&H0066595E&" --crop 500,150,1700,550 --out f.jpg`
(одна картинка, подпись с семьёй и недостающими глифами). Проверяй на реальной строке: у некоторых шрифтов
отдельные буквы нечитаемы (у LC Chalk «б» похожа на «5»). Для тайтла с пресетом шрифты уже выбраны — этот шаг
пропусти, если оформление не новое.

## Шаг 3. Сборка и проверка

```
TS build -c episode.json            # всё, 4 элемента параллельно (-j N); или перечисли id: ... fuego jack
```
На каждый элемент: `lines/<id>.json` и `check/<id>.jpg` (рендер через libass на первом/среднем/последнем кадре,
для движения — 5 кадров). **Открой каждый check** и пройди чек-лист:
1. японский текст и его свечение исчезли целиком, нет «призраков» по краям;
2. заплатку не видно: нет квадратиков, ступенек, пятен другого цвета, резкой границы;
3. на движении фон под заплаткой едет вместе с кадром (сравни первый и последний кадр);
4. русский текст на месте японского: та же базовая линия, центр, размер, не вылезает за орнаменты;
5. стиль совпадает: цвет, обводка/свечение, тень, размытость краёв как у оригинала;
6. ничего лишнего не закрыто (пуговицы, волосы, руки, элементы карточки).
Тонкие края на чек-листе мелкие — смотри крупно: `TS check -c episode.json yuno --frames 24800,24840
--zoom 120,740,720,1000 [--compare]` (`--compare`: оригинал | результат | разница ×4). Общий лист всех
элементов — `TS sheet -c episode.json`.
Плохо — поправь параметры этого элемента (подсказки в `references/troubleshooting.md`) и пересобери только его.

## Шаг 4. Сборка файла, превью, сабы

```
TS assemble -c episode.json             # -> cfg "out" (оригинал файла — копией в подпапку "исходники")
TS preview  -c episode.json             # mp4 со всеми надписями подряд, со звуком
TS merge    -c episode.json             # влить в сабы cfg "subs": старые надписи удаляются, слои — под диалогом
```
Строки заплаток при сборке уже ужаты без изменения картинки (~−23%, см. technique.md «Размер файла»).
Файлы, собранные до этого, ужимает `TS compact <надписи.ass> <сабы.ass>` (копия — «исходники/… (до сжатия)»).
Копии оригиналов, которые делают `assemble`/`merge`/`compact`, лежат в подпапке `исходники` рядом с файлом —
в папке релиза остаются только готовые файлы.
`merge` удаляет из сабов **только** строки переводчика тех надписей, что есть в конфиге и собраны
(точное совпадение времени, стиля и текста — CR делает надписи стилями диалога, удаление по стилю снесло бы
диалог), и строки прошлого merge (все наши строки помечены `Effect = ts`); `merge_drop_styles` — явный список
стилей, если надо. Остальные надписи переводчика остаются в сабах. Стиль удаляется, только если им больше
никто не пользуется. Добавляет `YCbCr Matrix` — без этой строки цвет заплаток поедет, не удаляй её.
merge печатает число строк диалога до и после (`dialogue lines: 304 -> 304 OK`) — они должны совпасть.

## Шаг 5. Отчёт пользователю

Коротко: что сделано по каждому типу надписей, где лежат файлы, какие шрифты положить в контейнер,
что посмотреть глазами в превью (ты видишь стоп-кадры — дрожание/мерцание в движении лучше проверит человек),
расхождения перевода. Приложи `preview.mp4` и общий контактный лист.

## Когда что-то нестандартное

- Персонаж проходит перед надписью → `occluders`: у `follow` — по тёмным силуэтам, у статичной `card` — по
  разнице кадра и чистого фона под заплаткой (покадровый `\iclip`). Для остальных типов: обрежь время/зону
  так, чтобы маска не лезла на персонажа, или сделай `text` без маски и скажи пользователю. Если такое
  повторяется — добавь `occluders` в нужный билдер.
- «Ящик» вокруг заплатки на светлом небе у движущейся карточки → сначала `check --zoom --compare`: обычно это
  ореол японского текста за краем маски (по умолчанию его забирает `halo`; проверь, что в логе сборки есть
  строка `halo: patch grows by ...`), реже — модель свечения (`"glow": "fit"`).
- 3D-перспектива (вывеска под углом) → маски нет, текст с `\frx\fry\frz`/`\fax` по 4 углам, замеренным
  `ruler`; это пока ручная работа — опиши, что сделал.
- Огромный размер файла (>1 МБ на элемент) → крупнее `encode.block`, меньше `maxK`, `rect_clip`; на быстрых
  проездах детали всё равно не видны.
- Что-то не получается за 2–3 итерации → вариант `text` без маски лучше, чем видимая заплатка.
